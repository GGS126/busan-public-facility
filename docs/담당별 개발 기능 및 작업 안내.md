# 담당별 개발 기능 및 작업 안내

작성일: 2026-11-05  
상태: 개발 작업 분담 초안

현재 계획서·SRS·SDD와 팀 역할을 기준으로, 각자 개발할 기능과 작업 범위를 정리했습니다.
개발 중 시설 규정이나 구현 상황에 따라 수정할 수 있으며, 최종 확정된 명세는 아닙니다.

담당 영역의 기술은 각자 선택합니다.
연결에 필요한 데이터·API 형식과 실행 방법은 관련 담당자끼리 맞춥니다.

## 서비스 전체 흐름

직접 입력 또는 자연어 입력
→ 이용조건 확인
→ 시설 검색·선택
→ 예상요금·예약·취소 조건 비교
→ 준비사항과 공식 예약 링크 안내

- AI는 자연어에서 이용조건을 추출합니다.
- 요금·감면 계산은 백엔드 규칙 엔진이 수행합니다.
- 시설·규정은 공식 자료를 확인해 DB에 저장합니다.
- 실제 예약·결제와 실시간 잔여석 확인은 제공하지 않습니다.

## 전체 담당 범위

| 담당 | 분야 | 최종적으로 맡을 범위 |
|---|---|---|
| 김승일 | 프론트엔드 | 조건 입력부터 검색·비교·준비사항까지 사용자 화면 |
| 배승환 | 백엔드 | 입력 검증, 검색, 요금 계산, 비교·준비사항 API |
| 왕연호 | DB·시설 데이터 | 공식 자료 조사, 데이터 구조, 저장·조회·적재 |
| 김규성 | AI·DevOps·프로젝트 관리 | 자연어 조건 추출, AI 실패 처리, 실행·검사·배포 환경과 진행 관리 |

## 김승일 — 프론트엔드

### 개발할 기능

| 기능 | 구현할 내용 | 확인 기준 |
|---|---|---|
| 직접 조건 입력 | 종목·지역·날짜·시간·감면 조건 입력 폼과 검색 버튼 | 입력값이 API로 전달되고 누락·잘못된 입력 안내 |
| 자연어 입력·확인 | 문장 입력창, 추출 조건 확인·수정 화면 | 수정한 조건으로 검색 가능, AI 실패 시 직접 입력으로 진행 |
| 시설 목록·선택 | 검색된 시설 목록, 기본정보, 비교 대상 선택 | 결과 없음 안내, 선택한 시설을 비교 요청에 전달 |
| 요금·규정 비교 | 시설별 요금 항목, 예약·취소·환불 조건 표시 | 백엔드 결과와 일치하고 ‘확인 필요’·출처·확인일 표시 |
| 준비사항·공식 링크 | 증빙서류·주의사항과 공식 예약 링크 표시 | 선택한 시설의 안내가 나오고 링크가 없으면 안내 |
| 공통 화면 처리 | 로딩·오류·모바일 화면과 참고용 고지 | 주요 흐름이 모바일에서도 동작하고 오류 후 재시도 가능 |

### 구현 방향

- 화면 초안은 예시 데이터로 먼저 만들 수 있습니다.
- API 형식이 정해지면 실제 백엔드 응답으로 연결합니다.
- 화면에서 요금을 따로 계산하거나 AI가 만든 금액을 표시하지 않습니다.
- 최초 납부액과 환급 후 예상 부담액을 구분해 표시합니다.

### 먼저 할 일

**직접 입력 폼과 시설 1곳의 요금 결과 화면부터 만듭니다.**

배승환과 입력값·결과 형식을 맞춘 뒤,
시설 목록 → 비교표 → 준비사항 → 자연어 입력 순으로 확장합니다.

## 배승환 — 백엔드

### 개발할 기능

| 기능 | 구현할 내용 | 확인 기준 |
|---|---|---|
| 입력 검증 | 직접 입력과 AI 추출 조건의 필수값·날짜·시간 검증 | 잘못된 요청에 항목별 오류 반환 |
| 검색·상세 조회 | 조건에 맞는 등록 시설 검색과 기본정보 조회 | 후보 목록·상세정보·출처 반환, 결과 없음 처리 |
| 요금 규칙 엔진 | 기본요금·추가요금·감면·환급 방식 처리 | 공식 자료로 만든 계산 사례와 결과 일치 |
| 비교 결과 생성 | 시설별 요금과 예약·취소·환불 조건 묶기 | 같은 이용조건으로 비교하고 항목별 근거 반환 |
| 준비사항 생성 | 감면 증빙·신청 제한·취소 주의사항 제공 | 사용자 조건과 시설 규정에 맞는 목록 반환 |
| AI 모듈 연결 | 추출 조건을 공통 입력 검증에 연결 | AI를 거치지 않아도 직접 입력·계산 동작 |
| 오류·로그 처리 | 공통 오류 응답과 개인정보 없는 로그 | 규정 누락·서버 오류 구분, 키·개인정보 비노출 |

### 구현 방향

- SDD의 검색·상세·비교·체크리스트 API 초안을 활용합니다.
- 시설 규정은 데이터로 관리하고 계산 로직과 분리합니다.
- 규정이 없거나 충돌하면 임의 계산하지 않고 사유와 ‘확인 필요’를 반환합니다.
- 금액 항목마다 사용한 규칙과 출처를 연결합니다.
- 규칙 엔진은 LLM을 호출하지 않습니다.

### 먼저 할 일

**시설 1곳의 규정과 이용조건을 받아 요금 결과를 반환하는 기능부터 만듭니다.**

왕연호와 필요한 데이터 항목을,
김승일과 요청·응답 형식을 맞춘 뒤 검색·비교·준비사항으로 확장합니다.

## 왕연호 — DB 및 시설 데이터

### 개발할 기능과 준비할 데이터

| 기능·작업 | 구현·정리할 내용 | 확인 기준 |
|---|---|---|
| 시설 후보 조사 | 같은 유형의 부산 시설 후보 3~5곳과 공식 자료 조사 | 비교 가능 여부와 규정 확보 여부 확인 |
| 규정 데이터 정리 | 기본요금·추가요금·감면·예약·취소·환불 조건 정리 | 출처·확인일·적용 시점과 불명확한 항목 구분 |
| DB 구조·저장 | 시설·규정·출처와 필요한 관계 구성 | 시설과 이용일에 맞는 규정 조회 가능 |
| 조회 연결 | 백엔드가 사용할 시설·규정 조회 기능 제공 | 합의한 형식으로 데이터 전달 |
| 데이터 적재·갱신 | 정리한 파일을 검사해 DB에 넣는 내부 도구 | 필수값 누락 시 적재 거부, 기존 데이터 유지 |
| 계산 검증 자료 | 실제 이용조건별 정답 계산 사례 작성 | 백엔드 계산 결과와 대조할 수 있도록 근거 기록 |

### 구현 방향

- DB 종류·구조와 조회 방식은 배승환과 맞춥니다.
- 요금 단위, 감면 적용 범위·중복 여부, 선결제 후 환급을 구분합니다.
- 모르는 규정은 추정해서 채우지 않고 미확인 상태로 남깁니다.
- 서비스 이용자의 질의 원문이나 감면 관련 개인정보는 저장하지 않습니다.
- 관리자 웹 화면 대신 내부 파일·적재 도구로 관리합니다.

### 먼저 할 일

**시설 1곳의 공식 규정과 계산 사례를 먼저 정리합니다.**

배승환이 계산 기능을 만들 수 있도록 데이터를 전달하고,
이후 같은 유형의 시설로 확대합니다.
최종적으로 공식 근거가 확인된 시설 3곳 이상 확보를 목표로 합니다.

## 김규성 — AI·DevOps·프로젝트 관리

### 개발할 기능과 관리할 작업

| 기능·작업 | 구현할 내용 | 확인 기준 |
|---|---|---|
| 자연어 조건 추출 | 문장에서 종목·지역·날짜·시간·감면 조건 추출 | 정해진 형식으로 반환하고 금액·자격을 임의 확정하지 않음 |
| 누락·모호성 처리 | 빠졌거나 불명확한 항목 표시와 재질문 정보 생성 | 추측으로 채우지 않고 사용자 확인·수정 가능 |
| AI 실패 처리 | 타임아웃·호출 실패·형식 오류 처리 | 화면에서 직접 입력으로 계속 진행 가능 |
| AI 개인정보 처리 | 전송 전 민감정보 제거 또는 전송 차단 | AI 요청과 로그에 개인정보가 남지 않음 |
| 실행 환경·CI | 실행 안내·환경변수 예시·자동 검사 구성 | 관련 팀원이 실행 가능하고 PR에서 합의한 검사 수행 |
| 배포·시연 환경 | 프론트·백엔드·DB·AI 설정 연결 | HTTPS 접근, 키 비노출, 핵심 흐름 시연 가능 |
| 진행·산출물 관리 | 일정·작업 현황·통합 확인과 최종 자료 취합 | 누락 작업과 주요 문제를 추적하고 문서 반영 |

### 구현 방향

- AI 입력·출력 형식과 백엔드 연결 방식은 배승환과 맞춥니다.
- 추출 결과는 사용자 확인 후 검색·계산에 사용합니다.
- AI는 요금 계산과 최종 감면 판정에 참여하지 않습니다.
- 결과를 자연어로 설명하는 기능은 핵심 기능 완성 후 여유가 있을 때 검토합니다.
- 실행에 필요한 버전·환경변수 이름·명령은 관련 담당자에게 받아 정리합니다.

### 먼저 할 일

**자연어 문장 → 검색 조건 추출의 작은 예시부터 만듭니다.**

동시에 다른 담당자의 실행 조건을 확인해 공통 실행 안내를 준비합니다.
이후 AI 실패 처리 → 화면·백엔드 연결 → 자동 검사·배포 순으로 확장합니다.

## 처음 연결할 기능

첫 통합 목표는 다음 흐름입니다.

**직접 조건 입력 → 시설 1곳의 규정 조회 → 예상요금 계산 → 화면에 근거와 함께 표시**

| 담당 | 첫 통합에서 맡을 일 |
|---|---|
| 왕연호 | 시설 1곳의 규정 데이터와 정답 계산 사례 제공 |
| 배승환 | 조건 검증·요금 계산과 결과 반환 |
| 김승일 | 입력 폼과 계산 결과 화면 연결 |
| 김규성 | 실행 환경 정리·통합 확인, AI 추출 실험 병행 |

이 흐름이 동작하면 시설 검색·복수 시설 비교·준비사항을 확장하고 AI 입력을 연결합니다.
각자 준비 작업은 병행하되, 연결에 필요한 형식은 구현 전에 관련 담당자끼리 맞춥니다.

## 공통 완료 기준

- 맡은 기능의 정상 동작과 주요 오류 상황을 확인합니다.
- API·데이터·실행 방법 변경 시 영향을 받는 담당자에게 알립니다.
- 출처가 필요한 결과에는 공식 URL과 확인일을 포함합니다.
- 검증 결과를 PR에 적고 다른 팀원 리뷰 후 develop에 병합합니다.
- 개발 중 작업 범위가 바뀌면 이 문서와 관련 Issue를 갱신합니다.
- 개발 마무리 단계에 사용 기술·버전·선택 이유를 김규성에게 전달합니다.
