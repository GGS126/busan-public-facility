# 개발 현황 및 남은 작업

기준일 2026-11-19 · 팀 공유용

**기본 화면·DB·요금 엔진은 구현됐고, 현재는 실제 데이터와 API를 연결해 서비스 전체를 완성하는 단계입니다.**
아래 내용은 계획서 v1.3, SRS v0.2, SDD v0.1, 역할별 작업 안내와 현재 PR·Issue를 대조한 현황입니다. PR 상태는 기준일 이후 달라질 수 있습니다.

다음 작업은 `develop`에 병합됐습니다.

## 앞으로 진행할 순서

1. **진행 중 PR 마무리** — #15 → #22 → #23 → #24의 수정본을 재리뷰합니다. #25 → #26 → #28도 남은 문제를 고친 뒤 순서대로 검토합니다. 두 흐름을 합칠 때 공통 파일과 응답 형식을 확인합니다.
2. **실제 데이터로 연결** — SQLite 규정을 공통 엔진으로 계산하고 `/api/compare`에서 반환합니다. #23 논의에 따라 휴장 판정은 비교 서비스에서 요금 계산 전에 처리합니다.
3. **화면 입력·결과 맞추기** — 유형별 감면 인원, 대표자 여부, 선택 조명 시간을 API에 전달합니다. 선결제액·현장 결제액·환급액·최종 부담액과 ‘확인 필요’를 구분해 표시합니다.
4. **실제 시설로 통합 시험** — 직접 입력과 AI 입력 각각에서 검색 → 상세·회차 확인 → 시설 2곳 이상 비교 → 준비사항·출처·예약 링크까지 확인합니다.
5. **배포·최종 정리** — CI·배포 환경을 구성하고, 요구사항 시험 결과·최종 문서·시연 자료를 정리한 뒤 검증된 코드를 `main`에 통합합니다.

요금 계산은 #25·#26의 공통 엔진으로 통일하기로 #23에서 의견을 공유했습니다. 실제 비교 API 연결은 배승환이 진행하고 김승일·김규성이 화면과 통합 동작을 확인합니다.

## 마지막에 함께 확인할 것

- 공식 계산 사례와 기본요금·조명료·감면 결과가 일치하는지
- 예약·취소·환불 조건, 증빙서류, 출처·확인일이 실제 시설에 맞게 나오는지
- 규정 누락·충돌·휴장·AI 실패 때 적절한 안내와 직접 입력이 동작하는지
- AI 평가 질의와 목표 정확도를 정하고 평가 결과를 기록했는지
- 시연 환경에서 비교 요청의 95% 이상이 3초 안에 표시되는지
- Chrome·Edge와 360px 모바일에서 주요 흐름이 동작하는지
- API 키 비노출, 개인정보 처리, HTTPS와 데이터 이용조건을 확인했는지
- 실제 기술·버전·실행 방법과 변경된 API·설계가 최종 문서에 반영됐는지

AI 결과 설명은 SRS에서 후순위 기능입니다. 우선 핵심 검색·계산·비교 흐름을 완성합니다.
