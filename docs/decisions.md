# 프로젝트 결정 기록

팀의 확정 사항과 앞으로 논의할 항목을 구분합니다.
새 결정을 내리면 결정일, 내용, 이유, 관련 Issue 또는 PR을 기록합니다.

## 현재 합의한 방향

- 프로젝트: 부산 공공시설 이용조건 비교·판정 서비스.
- 기본 개발 브랜치는 develop, 최종 안정 브랜치는 main.
- 기능 브랜치와 PR을 사용하고 다른 팀원의 리뷰 후 병합.
- 작업 관리는 GitHub Issues 사용.
- 김규성: AI 기능·DevOps·프로젝트 관리.
- 왕연호: DB·시설 데이터.
- 김승일: 프론트엔드.
- 배승환: 백엔드.
- AI는 자연어 조건 추출을 보조하고 최종 요금·감면 판정은 규칙 엔진이 수행.

## 개발 전 논의할 항목

| 항목 | 확인할 내용 |
|---|---|
| 기술 스택 | 프론트엔드·백엔드·DB·패키지 관리 도구 및 버전 |
| 시설 범위 | 동일 유형의 비교 가능한 후보 3~5곳 조사 후 선정 |
| 데이터와 API | SDD 초안을 기준으로 필수값·오류·확인 필요 상태 구체화 |
| 개발 환경 | 공통 실행 절차·환경변수 예시·테스트 및 CI |
| LLM | 제공자·모델·비용·호출 한도·평가 기준 |
| 일정과 배포 | 최종 발표일·중간 목표·배포 환경 |

React·TypeScript, FastAPI, SQLite, Docker 등 문서의 기술은 제안안이며 확정 사항이 아닙니다.
SDD의 AI 컴포넌트 담당 제안은 현재 역할 배분과 맞춰 후속 수정이 필요합니다.
실시간 잔여석 확인과 직접 예약·결제는 문서상 범위에서 제외되므로,
규정상 이용조건 충족과 실제 예약 가능 여부를 구분합니다.
