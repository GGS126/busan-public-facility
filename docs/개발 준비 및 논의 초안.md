# 개발 준비 및 논의 초안

작성일: 2026-11-05  
상태: 팀 검토용 초안

개발 전에 각자 준비할 내용과 함께 맞출 부분, 개발 순서를 정리합니다.
기존 프로젝트 계획서 v1.3, SRS v0.2, SDD v0.1과 현재 역할 배분을 기준으로 작성했습니다.


## 현재 정해진 방향

- 부산 공공시설의 예상요금·감면·예약·취소·환불 조건을 비교합니다.
- AI는 자연어에서 검색 조건을 추출하고 사용자가 확인·수정합니다.
- 최종 요금 계산과 감면 적용은 백엔드 규칙 엔진이 담당합니다.
- 근거가 없거나 규정이 충돌하면 임의 계산하지 않고 ‘확인 필요’로 표시합니다.
- 직접 예약·결제, 실시간 잔여석 확인, 관리자 웹 UI는 구현 범위에서 제외합니다.
- 규정상 이용조건 충족 여부와 실제 예약 가능 여부를 구분합니다.
- 작업은 Issue → 기능 브랜치 → PR → 다른 팀원 리뷰 → develop 병합으로 진행합니다.

## 각자 준비할 내용

| 담당 | 준비할 내용 | 관련 담당자와 맞출 내용 |
|---|---|---|
| 김규성 | AI 조건 추출 방식, 실행·배포 환경 | AI 입력·출력 형식, 필요한 환경변수, 실행·배포 방법 |
| 왕연호 | 시설 후보와 공식 규정 조사, 데이터 정리 | DB 종류·구조, 시설·규정 데이터 전달 방식 |
| 김승일 | 입력·검색·비교 화면 초안 | 화면에서 보내고 받을 정보, API 연결 |
| 배승환 | 검색·요금 계산 처리 방식과 API 초안 | 요청·응답 형식, DB 연결, AI 결과 처리 |

각자 익숙하고 일정 안에 구현할 수 있는 기술을 사용합니다.
사용 기술 전체를 팀에 따로 공하거나 승인을 받을 필요는 없습니다.
다만 다른 사람의 개발·실행·배포에 영향을 주는 선택은 작업 전에 관련 담당자와 확인합니다.

SDD의 React·TypeScript·Vite, FastAPI, SQLite 등은 참고할 제안이며 반드시 사용할 필요는 없습니다.

- DB 종류와 구조는 왕연호·배승환이 함께 정합니다.
- AI 연결은 김규성·배승환이 맞춥니다.
- 화면과 API 연결은 김승일·배승환이 맞춥니다.
- 실행·배포에 필요한 버전, 환경변수 이름, 실행 명령은 김규성과 관련 담당자가 공유합니다.

## 함께 정할 내용

| 항목 | 정할 내용 |
|---|---|
| 대상 시설 | 비교할 시설 유형과 최종 목록 |
| 구현 범위 | 첫 버전에 넣을 기능과 후순위 기능 |
| 연결 방식 | 화면·백엔드·DB·AI가 주고받을 정보 |
| 일정 | 최종 발표일, 첫 작업 기한, 중간 점검일 |

시설은 동일 유형의 비교 가능한 후보 3~5곳을 조사한 뒤 선정합니다.
기본요금뿐 아니라 추가요금·감면·예약·환불 조건, 출처 URL·확인일·데이터 이용조건을 확인해야 합니다.
문서의 시설 예시와 요금 예시를 실제 검증 데이터로 사용하지 않습니다.

## 개발 전에 맞출 세부 내용

SDD에 화면 흐름과 API 초안이 있으므로 이를 바탕으로 필요한 부분을 구체화합니다.

| 영역 | 맞출 내용 | 주로 함께 확인할 담당 |
|---|---|---|
| 화면 | 입력칸, 후보 선택 방식, 비교표 항목, 오류 표시 | 김승일·배승환 |
| 검색 조건 | 종목·지역·날짜·시간·인원·감면 유형의 필수 여부와 형식 | 김승일·배승환·김규성 |
| 시설·규정 데이터 | 요금 단위, 추가요금, 감면 중복 여부, 적용 기간, 출처·확인일 | 왕연호·배승환 |
| 계산 결과 | 최초 납부액·예상 환급액·환급 후 예상 부담액 구분 | 배승환·김승일 |
| AI 연결 | 추출할 조건, 응답 형식, 누락·오류·실패 처리 | 김규성·배승환·김승일 |
| 공통 API | 요청·응답 예시, 오류 형식, 변경 공유 방법 | 관련 담당자 |

직접 입력과 AI 추출은 같은 검색 조건 형식을 사용합니다.
AI 실패 시 직접 입력으로 진행할 수 있도록 하고, API 키와 개인정보가 응답·로그에 노출되지 않도록 합니다.
‘확인 필요’ 항목이 있으면 불완전한 합계를 확정 금액처럼 표시하지 않습니다.

모든 세부사항을 한 번에 정할 필요는 없습니다.
첫 기능을 연결하는 데 필요한 입력·출력과 데이터부터 맞춥니다.

## 역할별 첫 작업

| 담당 | 첫 작업 | 준비가 끝났다고 볼 기준 |
|---|---|---|
| 김규성 | AI 입력·출력 예시 작성, 실행·배포 방향 정리 | AI 연결 형식과 필요한 실행 환경 정리 |
| 왕연호 | 시설 후보·공식 규정 조사, 저장할 데이터 정리 | 시설 목록·출처·확인일과 시설 1곳의 계산 사례 공유 |
| 김승일 | 입력 → 후보 → 비교 화면 초안 작성 | 화면별 입력·표시 항목을 정리하고 백엔드와 확인 |
| 배승환 | API·규칙 엔진 처리 방식 정리 | 요청·응답 예시와 필요한 규정 항목을 관련 담당자와 확인 |

초안은 메모·표·간단한 그림으로 준비해도 됩니다.
처음부터 완성된 설계서나 기능 전체를 만들 필요는 없습니다.

연결되는 부분을 맞춘 뒤 개발 작업은 담당자·완료 기준·기한을 정해 Issue로 등록합니다.
SDD의 AI 컴포넌트 담당 제안은 현재 역할 배분과 맞춰 후속 갱신합니다.

## 개발 순서

| 단계 | 작업 | 완료 기준 |
|---|---|---|
| 1 | 시설 후보 조사와 담당 영역별 준비 | 시설 조사 결과와 화면·데이터·처리 방식 초안 준비 |
| 2 | 대상 시설·첫 기능 결정, 데이터·API 형식 맞추기 | 첫 기능의 입력·출력·규정 데이터 예시 정리 |
| 3 | 프로젝트 기본 구조와 실행 환경 구성 | 관련 팀원이 안내에 따라 실행하고 기본 동작 확인 |
| 4 | 시설 1곳으로 직접 입력 → 계산 결과 표시 | 공식 계산 사례와 결과 일치, 출처 표시 |
| 5 | 시설 확장과 검색·비교·체크리스트 구현 | 시설 2곳 이상 비교, 규정 누락·예외 표시 |
| 6 | AI 조건 추출 연동 | 사용자 확인·수정과 실패 시 직접 입력 동작 |
| 7 | 통합 테스트·배포·시연 및 최종 문서 정리 | 선정 시설 데이터 검증, SRS 인수 기준 점검, 담당별 기술 정보 취합 |

시설 1곳 구현은 중간 목표입니다.
최종 목표는 기존 계획에 따라 공식 근거가 확인된 동일 유형 시설 3곳 이상을 확보하고 핵심 기능을 검증하는 것입니다.

AI 담당자는 다른 기능 개발과 병행해 조건 추출을 실험할 수 있습니다.
화면 초안과 데이터 조사도 병행하되, 실제 연결 전에 공통 형식을 맞춥니다.

## 첫 통합 목표와 검증

첫 목표는 공식 규정이 확인된 시설 1곳에 대해 직접 입력한 조건으로 예상요금과 근거를 표시하는 것입니다.

기본요금·추가요금·감면·선결제 후 환급·규정 누락 사례를 실제 시설 규정에 맞춰 준비합니다.
예상 결과와 규칙 엔진 결과가 일치하는지 확인한 뒤 시설 비교로 확장합니다.

AI 조건 추출 정확도 목표·평가 질의 수와 성능 측정 환경·표본 수는 관련 담당자가 정리해 공유합니다.
비교 응답 시간 등 기존 SRS의 인수 기준도 시험 계획에 반영합니다.

## 공유와 기록

- 진행 상황과 막힌 점은 해당 Issue에 기록합니다.
- API·데이터 구조·실행 방법이 바뀌면 영향을 받는 담당자에게 알립니다.
- 작업 가능한 시간과 예상 소요 기간을 공유해 일정을 맞춥니다.
- 공동으로 결정한 사항은 [결정 기록](decisions.md)에 남깁니다.
- 범위나 설계가 바뀌면 관련 SRS·SDD·테스트 기준도 함께 갱신합니다.
- 최종 문서 작성에 필요한 사용 기술·버전·선택 이유는 개발 마무리 단계에 각자 김규성에게 따로 전달합니다.
- 실행에 필요한 버전·환경변수 이름·실행 명령은 마무리까지 미루지 않고 연결·실행할 때 공유합니다. 실제 API 키는 문서에 적지 않습니다.

## 핵심 요약

### 각자 지금 할 일

| 담당 | 우선 할 일 | 관련 담당자에게 전달할 것 |
|---|---|---|
| 김규성 | AI 조건 추출 예시와 실행·배포 방법 정리 | AI가 보내고 받을 정보, 실행에 필요한 설정 |
| 왕연호 | 같은 종류의 부산 시설 후보 3~5곳 조사 | 시설명·공식 링크·규정 확인 여부, 시설 1곳의 계산 예시 |
| 김승일 | 입력·검색·비교 화면 초안 만들기 | 화면에 필요한 입력칸과 서버에서 받아야 할 정보 |
| 배승환 | 검색·계산 처리 방식과 API 정리 | API 입력·출력 예시, 계산에 필요한 시설 데이터 |

**자기 담당 기술은 각자 선택해서 사용하면 됩니다.**
지금은 사용 기술 목록을 따로 제출할 필요가 없습니다.
다른 사람과 연결하는 데 필요한 정보만 관련 담당자에게 알려 주세요.

### 관련 담당자끼리 맞출 일

- **왕연호·배승환:** 어떤 DB를 쓰고, 시설·규정을 어떻게 저장할지
- **김승일·배승환:** 화면에서 어떤 정보를 보내고 받을지
- **김규성·배승환:** AI가 추출한 조건을 백엔드에 어떻게 전달할지
- **김규성·관련 담당자:** 각자 만든 것을 어떻게 실행하고 배포할지

### 다 같이 정할 일

1. 어떤 시설을 비교할지
2. 첫 버전에 어떤 기능을 넣을지
3. 각자 첫 개발 작업을 언제까지 끝낼지

### 그다음 시작할 개발

**시설 1곳을 대상으로 ‘직접 조건 입력 → 예상요금과 계산 근거 표시’부터 연결합니다.**
이 흐름이 동작하면 시설 검색·비교·준비사항을 확장하고 AI 입력을 연결합니다.

### 나중에 최종 마무리 때 

최종 문서와 발표자료 활용에 필요할 수도 있으니 각자 사용한 기술·버전·선택 이유를 간단히 정리해서 저에게 보내 주세요.
