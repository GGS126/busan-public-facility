# 비교 화면 비기능 검증 실행 안내

SRS AC-012의 비교 결과 표시 시간과 오류 후 복구를 실제 브라우저에서 확인합니다. 실제 Gemini 정확도 평가는 [AI 조건 추출 최종 검증 안내](AI%20조건%20추출%20최종%20검증%20안내.md)로 분리합니다.

## 준비

- Node.js 24, Chrome, 백엔드 의존성을 설치한 Python 3.13.
- 실제 SQLite DB를 생성하고 백엔드를 실행합니다. 감면 없는 직접 비교에는 Gemini 키가 필요 없습니다.
- 프론트엔드는 `VITE_USE_MOCK_API=false`로 빌드하고 실제 백엔드에 연결합니다.
- 로컬에서는 프론트엔드 폴더에서 `npm run build`, `npm run preview -- --host 127.0.0.1`로 빌드 결과를 실행할 수 있습니다. 기본 API 프록시는 127.0.0.1:8000입니다.
- 현재 시설 데이터의 적용기간 안에서 실행합니다. 이 도구는 다음 주 월요일을 이용일로 삼으므로 기간이 바뀌면 데이터를 갱신한 후 측정합니다.

브라우저 검사 도구 설치는 프로젝트의 다른 의존성과 분리되어 있습니다.

```powershell
cd scripts/browser-check
npm ci
cd ../..
node scripts/browser-check/compare.cjs --url http://127.0.0.1:4173 --output ../browser-performance.json
```

이미 설치된 Chrome을 사용하므로 별도 브라우저 다운로드는 하지 않습니다. Edge는 `--channel msedge`로 선택할 수 있습니다. 화면을 띄워 실행하려면 `--headed`를 붙입니다. 호스팅 측정 시에는 `--url`에 실제 서비스 주소를 지정합니다.

## 무엇을 측정하는가

1. 실제 검색 API로 다음 주 월요일 08:00~10:00의 삼락·구덕 테니스장을 검색하고 선택합니다.
2. 감면 없는 이용 인원 4명으로 두 시설의 비교 버튼을 누릅니다.
3. 버튼 클릭 이벤트부터 두 시설의 새 API 응답을 모두 받은 뒤 새 계산 결과가 DOM에 반영되고 애니메이션 프레임 두 번이 지날 때까지 브라우저 시계로 측정합니다. 클릭 전의 카드는 표시해 두고 측정 완료 조건에서 제외합니다.
4. 실제 비교 API 응답이 두 시설을 모두 포함하는지, 화면의 6,000원·8,000원과 새 계산 완료 카드 2개를 확인합니다. 시설별 호출과 한 번에 묶은 호출을 모두 허용합니다.
5. 첫 비교는 별도 기록하고, 이후 30회를 순차 측정합니다. 3초 이내 비율이 95% 이상인지 판정합니다.
6. 비교 API에 검사용 500 오류를 주입한 뒤 오래된 결과가 사라지는지, 오류 안내 후 재시도로 실제 결과가 복구되는지 확인합니다.
7. 가상 전화번호 입력은 실제 자연어 API에서 전송 전에 차단되고, 원문이 화면에 유지되는지 확인합니다.

오류 주입은 해당 테스트 브라우저의 요청에만 적용합니다. 서버·다른 사용자의 요청은 변경하지 않습니다. 개인정보 차단 검사에는 가상 번호를 사용하며 실제 개인 정보를 입력하지 않습니다. 일반 자연어의 실호출은 이 검사에서 수행하지 않습니다.

기본 표본 수는 30개이며 `--samples`로 20~200개를 지정할 수 있습니다. 결과 JSON은 표본별 시간, 비율, P95, 브라우저·운영체제·시간대·소스 커밋·작업 파일 변경 여부를 포함합니다. 오류가 나거나 시간 기준에 미달하면 종료 코드가 1입니다.

날짜는 PC 시간대와 무관하게 브라우저를 `Asia/Seoul`로 설정해 계산합니다. 시설 선택 뒤에는 고정 시간만 기다리지 않고 고정 회차 또는 자유시간 입력에 희망 시간이 반영될 때까지 기다립니다. 오류 안내 검사는 서버의 특정 문구 대신 시설 검색 영역의 오류 표시를 확인합니다.

측정기 회귀 검사는 `node --test scripts/browser-check/measurement.test.cjs`로 실행합니다. 이전 성공 카드가 남은 상태에서 API를 250ms·새 화면 반영을 100ms 지연해도 조기 완료하지 않는지, 묶음 호출에서도 동작하는지, API 응답이 없으면 실패하는지 확인합니다.

## 해석 범위

- 브라우저의 렌더링 프레임을 포함한 측정치이며 사람이 화면을 인지하는 시간을 직접 측정한 것은 아닙니다.
- 예열된 서버에서 순차 요청한 데스크톱 시나리오입니다. 동시 사용자 부하·모바일·절전 후 첫 기동은 따로 시험해야 합니다.
- 로컬 통과 결과를 공개 배포 환경 통과로 쓰지 않습니다.
- #32·#33·#34 등 최종 통합 후 같은 검사와 실제 감면·환불 흐름을 다시 확인합니다.
- 키·개인정보 비노출 전체와 HTTPS 적용 여부를 이 검사 하나로 판정하지 않습니다. 배포 환경의 서버 설정·응답·브라우저 자산도 별도로 확인합니다.
