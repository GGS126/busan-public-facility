# AI 조건 추출 최종 검증 안내

자연어 입력이 검색·요금 비교까지 이어지는지 확인하고, 최종 테스트 보고서에 쓸 실제 모델 평가 결과를 모읍니다.

## 이번에 확인한 범위

| 항목 | 결과 |
|---|---|
| 모의 추출 응답의 검증·누락 처리 | 평가 문장 18개 통과 |
| 실제 SQLite 검색·계산 연결 | 연동 테스트 4개 통과 |
| 기존 기능 회귀 검사와 평가 도구 검사 | Python 3.13 / Windows에서 364개 통과, 9개 제외 |
| 실제 Gemini 추출 정확도·응답시간 | 11/27 실호출 18개 전부 통과 |
| 화면에서 확인·수정·직접 입력 전환 | Chrome에서 아래 핵심 흐름 4개 통과, 감면 화면 등은 통합 후 추가 확인 |

모의 검증은 미리 정한 추출 응답을 입력해 서버 처리를 확인합니다. **모의 검증 통과율을 Gemini 정확도로 사용하지 않습니다.** 제외된 9개는 현재 `develop`의 취소·환불 사례이며, 환불 기능 PR이 들어오면 다시 확인합니다.

연동 테스트는 다음을 확인합니다.

- 추출한 날짜·지역·시간·인원으로 실제 DB를 검색하고, 일치하는 회차가 반환되는지
- 같은 조건을 직접 입력했을 때와 AI로 입력했을 때 계산 결과가 같은지
- 등록 시설이 없는 동래구를 유지하고, 결과 없음과 다른 지역 대안을 반환하는지
- 종료 시간을 보완하거나 AI 연결에 실패해도 직접 입력으로 검색할 수 있는지

이 검사는 서버 API까지의 확인입니다. 화면에서 지역·시간이 유지되는지는 프론트엔드 통합 후 별도로 확인합니다. 감면 인원과 대표자 여부는 사용자가 확인해서 입력하며 AI가 자격을 확정하지 않습니다.

## 평가 문장

`backend/evaluation/query_cases.json`에 18개를 정리했습니다.

- 명시 날짜, 내일·모레, 오전·오후, 숫자 시간, 자정
- 여러 지역, 등록 시설이 없는 지역
- 장애인·다자녀 감면
- 인원 생략, 날짜·시작·종료 시간·종목 누락, 모호한 날짜
- 전송 차단을 확인하는 가상 전화번호·이메일

날짜는 실행 당일의 한국 날짜를 기준으로 바뀝니다. 개인정보 사례는 실제 인물의 정보가 아닌 검사용 문장입니다.

## 실행 방법

저장소 루트에서 백엔드 의존성을 설치한 Python으로 실행합니다. 공통 실행 환경의 Python 3.13을 사용합니다.

```powershell
python database/build_db.py
python scripts/evaluate_query_parse.py
```

위 명령은 키 없이 모의 응답만 검증합니다. 실제 Gemini 평가는 다음 명령으로 분리합니다.

```powershell
python scripts/evaluate_query_parse.py --live --output ../ai-live-evaluation.json
```

`Gemini API key:`가 나오면 터미널에 키를 입력합니다. 입력 문자는 화면에 표시되지 않습니다. 키를 명령문·문서·PR에 붙여 넣지 않습니다. 이미 환경변수로 설정했다면 다시 입력받지 않습니다.

- 전체 18개를 순서대로 평가하며 요청 사이에 9초를 기다립니다. 약 3분 이상 걸릴 수 있습니다.
- 먼저 연결만 확인하려면 `--limit 3`을 붙입니다. 이 결과는 전체 평가 결과와 구분합니다.
- API 실패로 `llm_failed`가 나오면 이후 호출을 중단하고 실행한 개수를 기록합니다.
- 사용 중인 프로젝트의 무료 한도를 확인한 키로 실행합니다. 이 도구는 결제·요금제·모델 설정을 변경하지 않습니다.
- 응답과 키, 질의 원문은 결과 파일에 저장하지 않습니다. 사례 ID·항목별 일치 여부·처리 시간·모델·실행 환경·커밋을 기록합니다.
- 평가 실패나 중도 중단이면 종료 코드가 1입니다.

## 결과를 읽는 방법

`field_scores`는 종목·지역·날짜·시작 시간·종료 시간·인원·감면 유형별 일치 수와 평가 수입니다. 지역·감면 목록의 순서는 무시하고, 없는 값은 없는 값끼리 비교합니다. 개인정보 차단 2개는 항목별 정확도 분모에서 제외합니다.

각 문장은 항목 일치뿐 아니라 `status`와 `missing_fields`도 맞아야 통과합니다. 개인정보 사례는 별도로 차단 여부를 확인합니다. 모의 검증에서는 추출기 호출이 0회인지도 확인합니다.

`latency_ms`는 API를 같은 Python 프로세스에서 실행한 시간이며, 실호출에서는 Gemini 통신 시간이 포함됩니다. 브라우저 표시 시간·호스팅 서버까지의 통신·첫 기동 시간은 포함하지 않습니다. **이 수치를 SRS AC-012의 ‘비교 결과 95%가 3초 이내 표시’ 충족 근거로 사용하지 않습니다.**

SRS AC-003의 정확도 목표치는 팀 시험계획에서 정하도록 되어 있습니다. 이 문서에서는 임의로 합격 기준을 확정하지 않습니다. 최종 보고서에는 전체 실행 여부, 실제 측정값, 합의한 목표치와의 비교를 함께 적습니다.

## 최종 화면 확인

실제 API 모드에서 다음 흐름을 한 번씩 확인합니다.

1. 내일 테니스 이용 지역·시간·인원을 입력하고 추출값을 확인합니다.
2. 조건을 수정·확정한 후 검색하고, 일치하는 회차가 미리 선택되는지 확인합니다.
3. 시설을 선택해 비교하고 입력한 시간과 계산 근거·출처를 확인합니다.
4. 동래구처럼 등록 시설이 없는 지역에서 결과 없음·대안이 표시되는지 확인합니다.
5. 누락된 시간을 직접 보완하고, AI 오류가 나도 기존 문장을 유지하며 직접 입력으로 진행합니다.
6. 감면 유형을 고른 뒤 대상 인원·대표자 여부를 확인하고, 유형에 맞는 준비사항을 확인합니다.

브라우저 확인과 실호출에서 발견한 문제는 수정 후 같은 사례로 다시 확인합니다. API 테스트만 통과한 상태를 전체 시연 완료로 기록하지 않습니다.

## 11/27 실제 평가 결과

- 기준 커밋: `5bc9bc6`, 작업 파일 변경 없음. Python 3.13.17 / Windows 11.
- 모델: `gemini-3.5-flash-lite`.
- 전체 18개 실행·통과: 일반 조건 추출 16개, 개인정보 차단 2개.
- 7개 추출 항목 각각 16/16 일치. 개인정보 차단 사례는 항목별 정확도 분모에서 제외.
- 전체 18개 처리 시간: 중앙 순위값 2,693.98ms, P95·최대 5,795.67ms. 전송 전 차단 2개도 포함한 값.
- 사용자 실행 로그에서 일시적인 HTTP 503 한 번이 재시도로 복구된 것을 확인.
- [실행 결과 원본](test-results/query-parse-live-2026-11-27.json)에 사례별 결과를 기록. 키·질의 원문·외부 모델 응답은 포함하지 않음.

18개로 구성한 현재 평가 세트의 결과이며, 모든 자연어 입력의 정확도를 보장하는 수치가 아닙니다. 팀의 합격 목표치 확정과 배포 환경 측정은 별도입니다.

## 11/27 Chrome 화면 확인 결과

같은 커밋의 프론트엔드를 실제 브라우저(Chrome headless, 1440×1080)로 실행했습니다. AI 응답만 고정하고, 시설 검색·비교는 실제 백엔드와 SQLite DB를 사용했습니다. 실제 Gemini 호출과 브라우저 흐름 검사는 분리해 수행했습니다.

| 시나리오 | 확인 결과 |
|---|---|
| 사상구 테니스 12/1 08:00~10:00, 4명 | 확인 폼→검색 폼에 지역·시간·인원 유지, 삼락 테니스장 선택 시 회차 자동 선택, 실제 API와 화면에 6,000원 표시 |
