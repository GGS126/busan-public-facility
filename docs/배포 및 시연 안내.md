# 배포 및 시연 안내

프론트 빌드와 FastAPI를 **한 웹 서비스·한 주소**로 실행합니다. 브라우저는 같은 주소의 `/api`를 사용하고, Gemini 키는 서버에만 설정합니다. Vite 개발 서버나 별도 CORS 설정은 이 배포 방식에서 필요하지 않습니다.

## 구성

- Docker 빌드: Node 24로 `npm ci`·프론트 빌드 → Python 3.13 이미지에 백엔드·JSON·빌드 결과 복사
- 시작: `scripts/start_service.py`가 실제 JSON 8개로 DB를 재생성하고 FastAPI 실행
- 화면: `frontend/dist`만 제공. `.env`, DB, 서버 소스는 정적 공개 대상이 아님
- 상태 확인: `GET /api/health` (키·LLM 호출 없이 확인)
- 포트: `PORT` 환경변수 사용, 없으면 8000
- 프로세스: worker 1개. 현재 Gemini 호출 제한은 프로세스 단위이므로 임의로 worker를 늘리지 않음

규정 DB는 사용자 정보를 저장하지 않는 생성 결과물입니다. 무료 호스팅의 디스크가 초기화돼도 저장소의 JSON으로 복구합니다. 규정을 수정할 때는 JSON을 커밋하고 재배포합니다.

## 로컬 Docker 확인

Docker Desktop의 Linux 컨테이너 엔진을 시작하고 저장소 루트에서 실행합니다.

```powershell
docker build -t busan-public-facility .
docker run --rm --name busan-public-facility -p 8000:8000 busan-public-facility
```

<http://127.0.0.1:8000>에서 화면을 엽니다. 새 터미널에서 다음 검사를 실행할 수 있습니다.

```powershell
python scripts/check_deployment.py http://127.0.0.1:8000
```

키 없이 직접 입력·검색·계산이 동작합니다. 자연어를 확인할 때만 서버 환경변수로 기존 키를 전달하며, 이미지 빌드 인자나 프론트 환경변수에 키를 넣지 않습니다.

GitHub Actions `Container`도 PR에서 이미지 빌드와 키 없는 기동·화면/API 검사를 실행합니다. 실제 호스팅에 배포하지는 않습니다.

## Render 무료 웹 서비스 설정

배포 설정 파일은 `render.yaml`입니다. **현재 작업은 설정 코드 준비이며, Render 서비스 생성·외부 배포를 자동으로 실행하지 않습니다.**

1. 이 브랜치의 리뷰·병합이 끝난 뒤 Render에서 GitHub 저장소를 연결합니다.
2. Blueprint로 `render.yaml`을 읽거나, Docker Web Service를 만들고 브랜치를 `develop`, Dockerfile을 루트의 `Dockerfile`로 지정합니다.
3. **Free 플랜**을 확인합니다. 유료 DB·디스크·추가 서비스는 이 설정에 포함되지 않습니다.
4. 상태 확인 경로는 `/api/health`입니다. 포트는 Render의 `PORT` 값을 그대로 사용합니다.
5. 자연어가 필요하면 서비스 Environment에 `GEMINI_API_KEY`를 입력합니다. `GEMINI_MODEL`은 선택이며, 없으면 프로젝트 기본 모델을 사용합니다. 저장소나 이 문서에 실제 값을 적지 않습니다.
6. 최초 배포가 완료되면 제공된 HTTPS 주소에서 아래 점검을 합니다. 자동 재배포는 `off`이며 검증한 커밋을 수동 배포합니다.

Render 무료 웹 서비스는 15분간 요청이 없으면 절전되고 다음 요청에서 다시 기동합니다. 로컬 파일은 재시작·재배포 시 유지되지 않으므로 위 DB 재생성 방식을 씁니다. 무료 사용량과 빌드·트래픽 한도는 계정 대시보드에서 확인합니다. 한도를 넘어 유료 사용을 승인하지 않습니다. 자세한 조건은 [Render 무료 플랜](https://render.com/docs/free), [Docker 호스팅](https://render.com/hosting/docker), [Blueprint 설정](https://render.com/docs/blueprint-spec)을 확인합니다.

## 배포 후 확인

- [ ] `https://서비스주소/api/health`가 정상이고 화면·JS·CSS가 같은 주소에서 로드됨
- [ ] 직접 입력 → 시설 검색 → 회차/시간 선택 → 실제 요금·감면·출처·공식 링크 표시
- [ ] Gemini 키 미설정·실패·호출 제한 상황에서도 직접 입력 사용 가능
- [ ] 키 설정 후 자연어 조건 확인·수정·검색 동작 확인 (실제 호출 한도 안에서 별도 진행)
- [ ] HTTPS 주소 사용, 브라우저 코드·응답에 키가 노출되지 않음
- [ ] 새 JSON으로 재배포했을 때 규정 반영, 정기 휴장·확인 필요 표시

발표 전 HTTPS 주소를 미리 열어 절전에서 복구됐는지 확인하고 시연 흐름을 한 번 실행합니다. 응답 시간 측정에서는 서버가 기동된 상태의 결과와 절전 후 첫 기동 시간을 구분해 기록합니다. 공개 배포 성공·실제 모델 평가·성능 시험은 코드/컨테이너 검사 통과와 별도로 기록합니다.
